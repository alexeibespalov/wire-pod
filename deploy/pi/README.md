# Vector deployment on the Raspberry Pi

This fork's source of truth is this repo. The Pi is only a deployment target:
`deploy/pi/` here mirrors `~/wire-pod/` on the Pi (`john@192.168.1.39`, key `~/.ssh/rpi_key`).

```sh
./deploy/pi/deploy.sh --dry-run   # see what would change
./deploy/pi/deploy.sh             # sync + docker compose up -d
```

`deploy.sh` never touches the Pi's `.env` (secrets) or `data/` (wire-pod state).

## What runs

| Service | What | Network |
|---|---|---|
| `wire-pod` | upstream image `ghcr.io/kercre123/wire-pod:main`, with overlays below | host; chipper on **:8443** (Tailscale Funnel owns :443), web UI :8080, connCheck :80 |
| `vector-agent` | `<repo>/vector-agent`: LangGraph Functional-API ReAct agent behind wire-pod's "Custom" LLM provider. Persona, tools (motors, built-in behaviours, eyes, battery, memory), persistent threads | host, 127.0.0.1:8091 only; state in `agent-data/` |

Robot: Vector X4J8 (ESN 00609161), WireOS, `192.168.1.150` (router reservation),
server_config points at `192.168.1.39:8443` (IP mode; the router doesn't relay mDNS).

## Overlays on the upstream image

* **`intent-data/en-US.json`**: pruned voice-command keywords so more free-form speech
  reaches the LLM. Generated by `intent-data/build_intents.py` from the stock
  `chipper/intent-data/en-US.json`; test routing with
  `python3 intent-data/sim.py <stock.json> intent-data/en-US.json`.
* **`persist-sync.sh`**: workaround for an upstream bug: wire-pod saves settings with
  temp-file + rename, which replaces the image's symlink into `/data`, so web-UI settings
  were lost on container recreate. The wrapper copies them back to `data/` every 3 s.
  (The real fix belongs in `chipper/pkg/vars/files.go`: resolve symlinks before rename.)

## Pi-only files

* `~/wire-pod/.env`: see `.env.example` (chmod 600)
* `~/wire-pod/agent-data/`: agent state: `checkpoints.sqlite` (conversation threads),
  `memories.json` (long-term facts), `thread.json` (current thread),
  `logs/agent.log` (conversations, tool calls, presence, errors; rotating 5 MB x 5)
* `~/wire-pod/data/`: wire-pod state: settings, Vector's registration/session cert,
  speech model, SDK cert (`data/anki_vector/`)

## YouTube Music

Both agents play what the NAS library lacks from YouTube Music (`agent-core/agent_core/ytmusic.py`).
Catalogue songs need nothing. John's playlists and liked songs need his sign-in, which is a cookie
file in each agent's data folder (`agent-data/ytmusic/cookies.txt`, `cortana-data/ytmusic/cookies.txt`,
mode 600, owned by the container user). It is never in this repository.

- **Sign in, or renew it:** on the laptop run `./deploy/pi/ytmusic-login.py`. A small Chrome window
  opens on a profile kept only for this (`~/.local/share/vector-ytmusic`); sign in to Google, and the
  window closes by itself. The cookies go straight to the Pi over SSH and are picked up without a
  restart. If the profile is still signed in, the script finishes with no window at all.
- **When to run it:** when an assistant says its YouTube Music sign-in has expired.
- **Sign out:** delete the two `cookies.txt` files on the Pi and the profile folder on the laptop.
- **When YouTube changes something and tracks stop playing:** redeploy with `--no-cache` on the two
  agent images, which installs the newest yt-dlp. That is the fix nearly every time.
- **Ports:** Cortana serves stream addresses on `192.168.1.39:8097` for MPD on the Pi Zero. Only
  addresses signed by her are answered there. Vector's player uses his own `127.0.0.1:8091`.
- Using an account this way is outside YouTube's terms. yt-dlp's own guidance is that heavy use can
  get an account rate-limited or, rarely, suspended; one household playing songs is light use.

## Gotchas

* After wire-pod's SSH bot setup, Vector's login token is wiped: re-activate over BLE at
  https://wp.pvic.xyz (click ACTIVATE only, never flash its firmware).
* Double-pressing Vector's button **off** the charger toggles mic mute (persists across reboots).

## Exploration photos / sleep routine (vector-agent)

The agent's `/data/explore` (host: `~/wire-pod/agent-data/explore/`) holds photos Vector takes
while exploring (`photos/`, `captures.jsonl`) and the night-time VLM analysis (`analyses.jsonl`).
Disk is capped by `EXPLORE_MAX_PHOTOS` (default 500, about 15-30 MB). Both features are tunable
via the optional env vars in `.env.example` and need no change to the compose file.
